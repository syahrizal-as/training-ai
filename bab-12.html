Deployment AI

Strategi dan praktik terbaik untuk men-deploy aplikasi AI ke production: cloud, Docker, local LLM, VPS, monitoring, dan observability.

🎯 Tujuan Pembelajaran

  • Memahami opsi deployment AI: cloud (AWS, GCP, Azure), VPS, dan local (Ollama)
  • Mampu membuat Dockerfile dan docker-compose.yml untuk aplikasi AI
  • Memahami GPU vs CPU inference dan kapan menggunakan masing-masing
  • Menerapkan Nginx reverse proxy untuk production deployment
  • Mengimplementasikan monitoring dengan Prometheus + Grafana dan logging terstruktur

📋 Kompetensi Dasar

  • Mampu memilih strategi deployment berdasarkan kebutuhan (cloud vs on-premise vs local)
  • Mampu melakukan containerization aplikasi AI dengan Docker
  • Mampu mengkonfigurasi Nginx reverse proxy + SSL
  • Mampu setup monitoring stack untuk aplikasi AI production

12.2 Docker Containerization

Docker memungkinkan packaging aplikasi AI beserta dependensinya ke dalam container yang konsisten dan portable.

Contoh Dockerfile

# Dockerfile — Python FastAPI AI Service
FROM python:3.12-slim AS base

# Prevent Python from writing .pyc files and buffering stdout
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Install Python dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Create non-root user for security
RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app
USER appuser

# Health check
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
    CMD curl -f http://localhost:8000/health || exit 1

EXPOSE 8000

# Use multiple workers for production
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "4"]

  postgres_data:

💡 Best Practice: Gunakan multi-stage build untuk mengurangi image size. Gunakan non-root user. Selalu sertakan HEALTHCHECK. Gunakan .dockerignore untuk mengecualikan .git, __pycache__, .env, dan model weights dari build context.

12.3 Ollama — Local LLM Deployment

Ollama adalah platform open-source untuk menjalankan LLM secara lokal di laptop atau server tanpa ketergantungan cloud. Ollama menangani download model, quantization, dan serving dengan API OpenAI-compatible.

# Install Ollama (macOS/Linux)
curl -fsSL https://ollama.com/install.sh | sh

# Download dan jalankan model
ollama pull llama3.1:8b        # 8B parameter model (~4.7GB)
ollama pull deepseek-r1:7b     # DeepSeek reasoning model
ollama pull nomic-embed-text   # Embedding model for RAG

# Jalankan sebagai server API (OpenAI-compatible)
ollama serve
# API berjalan di http://localhost:11434/v1

# Test API
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.1:8b",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

Integrasi Ollama dengan Python

# Gunakan OpenAI client — Ollama kompatibel dengan OpenAI API
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"  # Ollama tidak butuh real API key
)

response = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Explain quantum computing briefly."}
    ],
    temperature=0.7,
    max_tokens=500
)

print(response.choices[0].message.content)

# Embedding
embed_response = client.embeddings.create(
    model="nomic-embed-text",
    input="What is retrieval augmented generation?"
)
print(f"Embedding dimension: {len(embed_response.data[0].embedding)}")

12.4 VPS Deployment & Nginx Reverse Proxy

Untuk deployment skala kecil-menengah, VPS (Virtual Private Server) dengan GPU atau high-CPU bisa menjadi pilihan cost-effective. Nginx berperan sebagai reverse proxy, SSL termination, dan load balancer.

Nginx Reverse Proxy Configuration

# /etc/nginx/sites-available/ai-api
upstream ai_backend {
    server 127.0.0.1:8000;
    server 127.0.0.1:8001;  # multiple workers
    keepalive 32;
}

# Rate limiting zone
limit_req_zone $binary_remote_addr zone=ai_limit:10m rate=30r/m;
limit_req_zone $binary_remote_addr zone=stream_limit:10m rate=10r/m;

server {
    listen 80;
    server_name ai.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name ai.example.com;

    # SSL (Let's Encrypt)
    ssl_certificate /etc/letsencrypt/live/ai.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ai.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # Max request body size (for file uploads)
    client_max_body_size 50M;

    # Gzip compression
    gzip on;
    gzip_types application/json text/plain application/javascript;

    # Main API endpoint
    location /api/ {
        limit_req zone=ai_limit burst=20 nodelay;
        proxy_pass http://ai_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeouts — AI responses can be slow
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_connect_timeout 60s;

        # Buffering off untuk streaming SSE
        proxy_buffering off;
        proxy_cache off;
    }

    # Streaming endpoint (no rate limit buffer)
    location /api/chat/stream {
        limit_req zone=stream_limit burst=5 nodelay;
        proxy_pass http://ai_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        
        # Disable proxy buffering for SSE
        chunked_transfer_encoding on;
    }

    # Health check
    location /health {
        proxy_pass http://ai_backend/health;
        access_log off;
    }

    # Static files
    location /static/ {
        alias /var/www/ai-app/static/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

12.5 GPU vs CPU Inference

AspekGPU InferenceCPU Inference
Kecepatan10-100x lebih cepat untuk LLMLambat untuk model >1B parameter
BiayaMahal — $2-30/jam (cloud GPU)Murah — standard instance pricing
Batch ProcessingIdeal — paralel tinggiTerbatas — core count dependent
Model Size7B-405B parameter (dengan quantization)Ideal untuk <3B parameter

📊 Rule of Thumb: Untuk production LLM serving dengan model 7B+, GPU adalah keharusan. Untuk embedding generation, reranking, atau model <1B parameter, CPU dengan optimasi (ONNX Runtime, quantization) sudah cukup.

12.6 Monitoring & Logging

12.6.1 Prometheus Metrics

# monitoring.py — Prometheus metrics untuk AI service
from prometheus_client import Counter, Histogram, Gauge, generate_latest
from fastapi import FastAPI, Response
import time

app = FastAPI()

# Metrics definitions
ai_requests_total = Counter(
    'ai_requests_total',
    'Total AI API requests',
    ['provider', 'model', 'status']
)

ai_request_duration_seconds = Histogram(
    'ai_request_duration_seconds',
    'AI request latency in seconds',
    ['provider', 'model'],
    buckets=[0.1, 0.5, 1.0, 2.0, 5.0, 10.0, 30.0, 60.0, 120.0]
)

ai_tokens_used_total = Counter(
    'ai_tokens_used_total',
    'Total tokens consumed',
    ['provider', 'model', 'type']  # type: prompt, completion
)

ai_cost_usd_total = Counter(
    'ai_cost_usd_total',
    'Total cost in USD',
    ['provider', 'model']
)

ai_active_requests = Gauge(
    'ai_active_requests',
    'Number of requests currently being processed'
)

@app.middleware("http")
async def metrics_middleware(request, call_next):
    """Record metrics for every AI request."""
    ai_active_requests.inc()
    start_time = time.time()

    response = await call_next(request)

    duration = time.time() - start_time
    ai_active_requests.dec()

    # Record duration for AI endpoints
    if request.url.path.startswith("/api/ai/"):
        provider = getattr(request.state, 'provider', 'unknown')
        model = getattr(request.state, 'model', 'unknown')
        status = 'success' if response.status_code < 400 else 'error'

        ai_requests_total.labels(
            provider=provider, model=model, status=status
        ).inc()
        ai_request_duration_seconds.labels(
            provider=provider, model=model
        ).observe(duration)

    return response

@app.get("/metrics")
async def metrics():
    """Prometheus scrape endpoint."""
    return Response(
        content=generate_latest(),
        media_type="text/plain"
    )

12.6.3 Structured Logging (Python)

# logging_config.py — Structured logging with JSON format
import logging
import json
import time
from datetime import datetime, timezone

class StructuredFormatter(logging.Formatter):
    """JSON structured logging formatter."""
    
    def format(self, record):
        log_entry = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
        }
        
        # Include extra fields
        for key in ['request_id', 'user_id', 'provider', 
                     'model', 'tokens', 'latency_ms', 'cost_usd']:
            if hasattr(record, key):
                log_entry[key] = getattr(record, key)
        
        # Include exception info if present
        if record.exc_info and record.exc_info[0]:
            log_entry["exception"] = {
                "type": record.exc_info[0].__name__,
                "message": str(record.exc_info[1])
            }
        
        return json.dumps(log_entry, default=str)

# Usage in AI service
logger = logging.getLogger("ai.service")

def log_ai_call(provider, model, prompt_tokens, completion_tokens, 
                latency_ms, cost_usd, status="success"):
    """Log AI API call with structured metadata."""
    logger.info(
        f"AI call: {provider}/{model}",
        extra={
            "provider": provider,
            "model": model,
            "tokens": prompt_tokens + completion_tokens,
            "latency_ms": latency_ms,
            "cost_usd": cost_usd
        }
    )

12.7 Ringkasan

  • Cloud Deployment: AWS (SageMaker, Bedrock), GCP (Vertex AI), Azure (AI Studio). Pilih berdasarkan ekosistem, kebutuhan GPU/TPU, dan compliance.
  • Docker Containerization: Dockerfile multi-stage + docker-compose untuk full stack (API + DB + Redis + Nginx + Monitoring). Gunakan non-root user, HEALTHCHECK, dan resource limits.
  • Ollama: Local LLM deployment yang mudah dengan API OpenAI-compatible. Ideal untuk development, testing, dan use case privacy-sensitive.
  • VPS + Nginx: Nginx sebagai reverse proxy dengan SSL termination, rate limiting, SSE streaming support, dan caching.
  • GPU vs CPU: GPU untuk production LLM 7B+; CPU cukup untuk embedding, reranking, dan model kecil (<3B).
  • Monitoring: Prometheus metrics (latency, error rate, token usage, cost) + Grafana dashboards + structured JSON logging.

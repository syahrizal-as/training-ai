7.1 Definisi Vector Database

Apa itu Vector Database?

Vector Database adalah sistem database yang dirancang khusus untuk menyimpan, mengindeks, dan mencari data dalam bentuk vektor embedding berdimensi tinggi. Tidak seperti database tradisional yang mencari berdasarkan pencocokan eksak (exact match) atau range query, vector database mencari berdasarkan kemiripan semantik — menemukan vektor yang paling mirip dengan vektor query menggunakan metrik seperti cosine similarity.

📖 Mengapa diperlukan? Database tradisional (SQL, NoSQL) tidak dioptimalkan untuk operasi similarity search pada vektor berdimensi tinggi. Linear scan (membandingkan query dengan semua vektor satu per satu) menjadi sangat lambat ketika data mencapai jutaan atau miliaran vektor. Vector database menggunakan Approximate Nearest Neighbor (ANN) algorithms untuk mempercepat pencarian.

(SQL/NoSQL)		Vector Database
Tipe DataStructured (rows, columns), JSON, key-valueDense vectors (float arrays) + metadata
QueryExact match, range, JOINs, aggregationsSimilarity / Nearest Neighbor (ANN)
IndexB-Tree, Hash, Inverted Index, GiSTHNSW, IVF, PQ, DiskANN
Akurasi Query100% exact (by default)Approximate (tunable accuracy vs speed)

💡 Tidak mutually exclusive: Vector database dan database tradisional bukan "salah satu atau yang lain". Arsitektur modern sering menggabungkan keduanya: PostgreSQL untuk data transaksional + PGVector untuk similarity search, atau MongoDB (NoSQL) + dedicated vector index. Pattern ini disebut polyglot persistence.

7.3 Pinecone

Overview

Pinecone adalah vector database fully-managed cloud-native yang dirancang khusus untuk production workloads. Tidak ada opsi self-hosted — semuanya berjalan di cloud Pinecone. Fokus pada kemudahan penggunaan, skalabilitas otomatis, dan performa tinggi tanpa operational overhead.

Fitur Utama

FiturDeskripsi
DeploymentCloud-only (AWS, GCP, Azure). Serverless atau pod-based.
IndexingProprietary ANN (pod-based) + serverless index
Metadata Filtering✅ Single-stage filtering (filter before/after ANN)
Hybrid Search❌ Tidak native (perlu integrasi terpisah)
Dimensi Maks20,000 dimensi
SDKPython, TypeScript, Java, Go
HargaFree tier (1 pod), paid dari ~$70/bulan
from pinecone import Pinecone, ServerlessSpec

# Inisialisasi
pc = Pinecone(api_key="YOUR_API_KEY")

# Buat index
pc.create_index(
    name="my-docs",
    dimension=1536,
    metric="cosine",
    spec=ServerlessSpec(cloud="aws", region="us-east-1")
)

# Insert vectors
index = pc.Index("my-docs")
index.upsert(vectors=[
    ("doc1", [0.1, 0.2, ..., 0.3], {"title": "AI Basics"}),
    ("doc2", [0.4, 0.5, ..., 0.6], {"title": "ML Advanced"}),
])

# Query
results = index.query(
    vector=[0.15, 0.25, ..., 0.35],  # query embedding
    top_k=5,
    filter={"title": {"$eq": "AI Basics"}},  # metadata filter
    include_metadata=True
)

7.4 Chroma

Overview

Chroma adalah vector database open-source yang dirancang untuk kemudahan pengembangan (developer-friendly). Chroma sangat populer di kalangan AI engineer karena integrasi native dengan framework seperti LangChain dan LlamaIndex, serta kemampuannya berjalan secara embedded (in-process) maupun client-server.

Fitur Utama

FiturDeskripsi
DeploymentSelf-hosted open-source + Chroma Cloud (beta)
IndexingHNSW (via hnswlib)
Metadata Filtering✅ Basic filtering (eq, ne, gt, lt, in)
Hybrid Search❌ Tidak native
Embedding Integration✅ Built-in: OpenAI, Cohere, HuggingFace, dll
SDKPython, JavaScript (first-class)
HargaOpen-source (free), Cloud: TBD
import chromadb

# Inisialisasi client (embedded mode)
client = chromadb.PersistentClient(path="./chroma_data")

# Buat collection
collection = client.create_collection(
    name="my_docs",
    metadata={"hnsw:space": "cosine"}
)

# Insert vectors
collection.add(
    documents=["AI adalah kecerdasan buatan", "ML adalah subset AI"],
    metadatas=[{"topic": "AI"}, {"topic": "ML"}],
    ids=["doc1", "doc2"]
)

# Query
results = collection.query(
    query_texts=["apa itu artificial intelligence?"],
    n_results=5,
    where={"topic": "AI"}  # metadata filter
)
print(results["documents"])
⚠️ Catatan: Chroma sangat cocok untuk prototyping dan project skala kecil-menengah. Untuk production skala besar (miliaran vektor), pertimbangkan Milvus atau Pinecone. Chroma Cloud masih dalam tahap awal (beta).

7.5 Milvus

Overview

Milvus adalah vector database open-source cloud-native yang dirancang untuk skala miliaran vektor. Dikembangkan oleh Zilliz, Milvus menggunakan arsitektur disaggregated storage & compute — memisahkan storage, indexing, dan query ke komponen terpisah untuk skalabilitas horizontal.

Fitur Utama

FiturDeskripsi
DeploymentSelf-hosted (Docker/K8s) + Zilliz Cloud (managed)
IndexingHNSW, IVF_FLAT, IVF_SQ8, IVF_PQ, DiskANN, GPU IVF
Metadata Filtering✅ Advanced: scalar filtering, boolean expressions
Hybrid Search✅ Native: BM25 + vector (since v2.4)
Dimensi Maks32,768 dimensi
Skalabilitas✅ Horizontal scaling, miliaran vektor
SDKPython, Java, Go, Node.js, RESTful
HargaOpen-source (free), Zilliz Cloud: free tier + usage-based
from pymilvus import MilvusClient, DataType

# Inisialisasi client
client = MilvusClient("./milvus_demo.db")  # local / bisa remote

# Buat schema + collection
schema = client.create_schema(auto_id=True)
schema.add_field("id", DataType.INT64, is_primary=True)
schema.add_field("vector", DataType.FLOAT_VECTOR, dim=1536)
schema.add_field("title", DataType.VARCHAR, max_length=256)

client.create_collection(
    collection_name="my_docs",
    schema=schema,
    index_params={
        "metric_type": "COSINE",
        "index_type": "HNSW",
        "params": {"M": 16, "efConstruction": 200}
    }
)

# Insert vectors
client.insert("my_docs", [
    {"vector": [0.1, 0.2, ..., 0.3], "title": "AI Basics"},
    {"vector": [0.4, 0.5, ..., 0.6], "title": "ML Advanced"},
])

# Query
results = client.search(
    collection_name="my_docs",
    data=[[0.15, 0.25, ..., 0.35]],
    limit=5,
    filter='title like "AI%"',
    output_fields=["title"]
)

7.6 Weaviate

Overview

Weaviate adalah vector database open-source dengan arsitektur GraphQL-native dan dukungan hybrid search (vector + keyword) built-in. Weaviate menonjol karena kemampuannya menggabungkan semantic search dengan BM25 keyword search dalam satu query, serta dukungan untuk multi-tenancy.

Fitur Utama

FiturDeskripsi
DeploymentSelf-hosted (Docker/K8s) + Weaviate Cloud (WCD)
IndexingHNSW + Flat (brute-force) + PQ (compression)
Metadata Filtering✅ Advanced with GraphQL where filters
Hybrid Search✅ Native: BM25 + Vector (alpha tuning)
Multi-Tenancy✅ Built-in tenant isolation
Embedding Integration✅ Auto-vectorization (OpenAI, Cohere, HuggingFace)
API StyleGraphQL-first + REST
HargaOpen-source (free), Cloud: free sandbox + paid
import weaviate

# Inisialisasi client
client = weaviate.connect_to_local()  # atau Weaviate Cloud

# Buat collection
collection = client.collections.create(
    name="MyDocs",
    properties=[
        weaviate.Property(name="title", data_type=weaviate.DataType.TEXT),
        weaviate.Property(name="content", data_type=weaviate.DataType.TEXT),
    ],
    vectorizer_config=weaviate.Configure.Vectorizer.text2vec_openai()
)

# Insert dokumen (auto-vectorized)
collection.data.insert({
    "title": "AI Basics",
    "content": "Artificial Intelligence adalah..."
})

# Hybrid search (vector + keyword)
results = collection.query.hybrid(
    query="apa itu artificial intelligence?",
    alpha=0.5,  # 0 = pure keyword, 1 = pure vector
    limit=5,
    return_properties=["title", "content"]
)
💡 Keunggulan Weaviate: Hybrid search native adalah fitur paling membedakan. Sistem bisa mencari dengan kombinasi semantic similarity + keyword matching dalam satu query. Sangat cocok untuk search engines dan RAG systems yang butuh precision tinggi.

7.7 PGVector

Overview

PGVector adalah PostgreSQL extension yang menambahkan kemampuan vector search ke PostgreSQL. Alih-alih database terpisah, PGVector memungkinkan penyimpanan vektor dan metadata dalam tabel PostgreSQL yang sama — ideal untuk tim yang sudah menggunakan PostgreSQL dan ingin menambahkan vector search tanpa operational overhead database baru.

Fitur Utama

FiturDeskripsi
DeploymentPostgreSQL extension (self-hosted) atau Supabase/Neon/Tembo (managed)
IndexingIVFFlat, HNSW (since v0.5.0)
Metadata Filtering✅ Full SQL WHERE clauses + JOINs
Hybrid Search✅ Manual: vector search + text search (tsvector)
Dimensi Maks2,000 dimensi (recommended)
SkalabilitasVertical (PG single node). ~10-50M vektor practical limit.
ACID✅ Full transactional support
HargaOpen-source (free). Managed: Supabase free tier+
-- Enable PGVector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Buat tabel dengan kolom vektor
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT,
    embedding vector(1536),    -- Dimensi 1536 (text-embedding-3-small)
    created_at TIMESTAMP DEFAULT NOW()
);

-- Buat index HNSW
CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops);

-- Insert data
INSERT INTO documents (title, content, embedding)
VALUES (
    'AI Basics',
    'Artificial Intelligence adalah...',
    '[0.012, -0.453, 0.789, ...]'::vector
);

-- Vector similarity search + metadata filtering
SELECT id, title, content,
       1 - (embedding <=> '[0.015, -0.448, 0.792, ...]'::vector) AS similarity
FROM documents
WHERE created_at > '2026-01-01'
ORDER BY embedding <=> '[0.015, -0.448, 0.792, ...]'::vector
LIMIT 10;
⚠️ Keterbatasan PGVector: Tidak didesain untuk skala miliaran vektor seperti Milvus. Indexing HNSW bisa lambat untuk dataset sangat besar (>50M). Tidak ada native hybrid search — perlu dikombinasikan manual dengan PostgreSQL full-text search (tsvector).

7.8 Indexing: HNSW & IVF

Mengapa Perlu Indexing?

Tanpa index, vector database harus melakukan brute-force scan — membandingkan query vector dengan setiap vektor di database. Untuk N vektor, ini O(N) per query. Dengan jutaan atau miliaran vektor, ini tidak praktis. ANN (Approximate Nearest Neighbor) indexing mengorbankan sedikit akurasi untuk kecepatan yang jauh lebih tinggi.

HNSW (Hierarchical Navigable Small World)

HNSW adalah algoritma ANN berbasis graph yang membangun struktur multi-layer. Layer atas memiliki sedikit node (long-range connections), layer bawah memiliki banyak node (local connections). Pencarian dimulai dari layer atas dan turun ke bawah — mirip seperti "skip list" untuk vektor.

IVF (Inverted File Index)

IVF (Inverted File Index) menggunakan clustering: vektor data dikelompokkan menjadi N clusters (menggunakan K-means). Saat query, hanya cluster-cluster terdekat yang dicari — bukan seluruh database. IVF lebih hemat memory dibanding HNSW, tapi akurasinya bergantung pada jumlah cluster yang di-probe.

7.10 Ringkasan

  • Vector Database menyimpan dan mencari vektor embedding berdasarkan kemiripan semantik, bukan pencocokan eksak seperti database tradisional.
  • Pinecone: Cloud-only, zero ops, serverless option. Ideal untuk tim yang tidak ingin mengelola infrastruktur.
  • Chroma: Open-source, developer-friendly, embedded mode. Ideal untuk prototyping dan project skala kecil-menengah.
  • Milvus: Open-source cloud-native, skalabilitas horizontal hingga miliaran vektor. Cocok untuk production skala besar.
  • Weaviate: Open-source, GraphQL-native, hybrid search (BM25 + vector) built-in. Cocok untuk search engines dan RAG.
  • PGVector: PostgreSQL extension. Ideal jika sudah menggunakan PostgreSQL — tidak perlu database tambahan.
  • Indexing: HNSW (graph-based, cepat, memory tinggi) vs IVF (cluster-based, hemat memory, perlu tuning).
  • Pemilihan: Tergantung skala data, kebutuhan hybrid search, self-hosted vs managed, dan existing infrastructure.

🏋️ Latihan

  1. Chroma Setup: Install Chroma via pip, buat collection, insert 50 vektor embedding (dari OpenAI text-embedding-3-small), dan lakukan 10 query semantic search. Catat response time rata-rata.
  2. PGVector Integration: Di PostgreSQL lokal atau Supabase, enable pgvector extension. Buat tabel dengan kolom vector(1536), insert data yang sama seperti latihan Chroma, dan bandingkan query performance.
  3. HNSW Tuning: Gunakan Milvus dengan index HNSW. Variasikan parameter M (8, 16, 32, 64) dan efConstruction (100, 200, 400). Plot trade-off antara recall, QPS, dan memory usage.
  4. Hybrid Search: Gunakan Weaviate untuk implementasi hybrid search. Bandingkan hasil pure vector search vs hybrid search (alpha=0.5) untuk 10 query yang mengandung nama produk spesifik. Kapan hybrid search lebih baik?
